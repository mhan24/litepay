# LitePay

开发阶段的 Binance / OKX 站内转账收银台，使用 Go、Gin、SQLite，提供 BEpusdt JSON 接口。仅支持 USD 订单及 USDT / USDC，尚未完成真实付款与商城交付验收。

## 开发运行

使用 Go 1.26。复制 `config.example.yaml` 为 `config.yaml`，设置管理员密码，然后运行：

```sh
go run . -config config.yaml
```

默认数据库为 `data/litepay-dev.db`。首次启动后到 `/admin/settings` 配置只读 API 凭据、收款 UID、币种和金额规则；到接入页读取生成的 BEpusdt Token。可以自定义后台入口及首页商店跳转地址。API 凭据仅需读取权限，不启用交易或提现。

本版本采用全新 Schema（版本 8），拒绝打开旧版非空数据库。使用新的空数据库路径即可初始化；没有历史迁移、恢复或兼容路径。不要把它指向生产数据库。配置及数据库包含密钥，不要提交到 Git。

## 核心处理

交易所 API → 统一交易证据 → 精确条件匹配 → SQLite 原子核销 → 回调任务 → 商户确认。

- 金额使用整数微单位（六位小数）；超过精度且非零的尾数直接拒绝，绝不四舍五入。应付金额向上对齐显示精度后分配独占档位。
- 交易以 `(provider, event_id)` 唯一。到账证据与核销归属共用一张表，订单归属也有唯一约束。
- Binance 使用原始 `transactionId`；可用的 `orderId` 只用于查找。多个资产明细保留为一个歧义事件，禁止自动认领。
- OKX 使用充值 `depId`；`fromWdId` 仅为查询参考号。缺少可靠 ID 或分页未完整完成时整个查询失败，不推进扫描进度。
- 核销要求平台、UID、币种、完整金额、付款时间窗口全部匹配，且只有一个候选订单。自动扫描与用户主动查款共用 `store.Process`，是否可核销只看订单与金额档位是否仍处于占用状态，不看扫描器读到这笔流水的时间。
- 自助查款在选择付款方式一分钟后开放，每单最多 10 次、间隔至少一分钟。用户填写金额不作为付款证据。
- 订单只有在成功扫描覆盖完整付款窗口（含宽限期）之后才会过期；交易所查询失败或扫描落后时订单保持待付款，仍可能按时付款的订单不会被永久关闭。窗口内出现交易所尚未确认的到账时，订单额外保留到补查上限（有效期 + 回看缓冲 + 宽限期）。
- 扫描器只在存在等待付款的订单、或存在仍可能落进付款窗口的未确认到账时才请求交易所历史；空转时跳过请求并保持扫描游标不变，下次补查从上次真正读到的位置继续。首次扫描与仍处于补查期的未确认到账都会把查询窗口拉回到它们原始的时间：交易所历史按记录创建时间分页，状态变化不会移动记录，游标越过之后就再也读不到。
- 重选、取消及支付成功后，旧金额档位保留至原付款窗口与宽限期结束；订单关闭后该档位立即释放。宽限期仅用于发现窗口内付款；最终过期后不自动重开订单。
- 已支付状态、资金归属及回调任务在同一数据库事务提交。仅发送 `status=2` 成功回调，不发送过期通知。
- 回调用递增尝试次数隔离过期执行者，保留有限重试及结果日志。仅 2xx 且正文 `success` / `ok` 为商户确认；交付幂等由商城实现。
- 后台只展示证据与状态，没有绕过交易唯一约束的强制支付入口。

`/healthz` 检查数据库连通；`/readyz` 还要求已配置的平台最近成功完成扫描且进度没有积压（没有待付款订单的空闲期不要求游标新鲜）。后台可查看未归属事件、扫描错误及未确认回调。对歧义或最终关闭后的到账，保留证据并交由人工在商城和交易所核对。

## 验证与容器

```sh
go test ./...
go test -race ./...
go vet ./...
go build ./...
docker build -t litepay:dev .
```

Dockerfile 以非 root 用户运行。自行挂载配置及可写数据目录。仓库不再包含生产部署、回滚、备份和恢复演练工具。模拟测试通过不能替代真实交易所字段、只读权限、到账延迟及商城幂等交付的实际验收。
