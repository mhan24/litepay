## 3. 前置准备

1. **后台配置（`/admin/settings`）**：核对目标平台的只读 API 凭据（OKX 与 Bitget 需同时配置 Passphrase）、主账号收款 UID、开放币种（USDT / USDC）、收银台平台排序、应付精度（默认 2 位）、最小应付金额、金额步长与最大调整次数。
2. **商户接入配置（`/admin/integration`）**：确认 BEpusdt 接入地址、Token 与商城网关配置一致。
3. **测试金额建议**：验收金额建议 **≥ 1 USDT / USDC**（规避交易所最小站内转账限额），并确保订单总额在 `[0.0001, 1000000)` 区间内。
4. **明确付款账户**：明确本次验收的**唯一付款方账户**（必须与商户收款 UID 不同，且为已完成实名认证可发起站内转账的独立账户）。

## 8. 失败与终止处理原则

- **超时未核销**：若超过订单有效期及宽限期仍未自动核销，**切勿重复付款**；完整保留转账截图与交易编号，将 `provider / 事件编号 / 金额 / 时间` 提供给管理员在交易所与商城端人工核对。
- **回调未确认**：若商户回调始终未获确认，记录 LitePay 后台尝试的 HTTP 状态码、错误信息及商城端日志；商户确认成功前，商城端不会触发商品发货。
- **金额不一致**：若实际转账金额与应付金额存在任何微小差异，网关机制严格禁止自动核销并保留流水证据；此类订单必须由人工介入在商城侧线下处理，严禁手工篡改金额再次提交。
- **单一凭证原则**：单一凭证仅限执行一次小额验收；验收结论仅针对对应账户、指定币种及该时间段有效。
