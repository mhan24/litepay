# GRAM 收款与定期检测

LitePay 基于 Toncenter v2 接口接收 TON 主网原生代币 GRAM，支持商户以 USD 计价创建商城订单。收款钱包地址为标准钱包地址，非 Jetton 代币合约；GRAM 支付走链上直接转账，不经过 Binance / OKX 站内转账通道。

---

## 配置与运行

1. **启用币种**：启动 LitePay，进入管理后台「支付设置」，在开放币种中勾选 **GRAM**。
2. **配置收款钱包**：在「GRAM · TON 主网」区域填写商户收款钱包地址（`Toncenter API Key` 为可选填项）。确保持有该收款钱包后保存配置；公开只读接口仅能查询链上数据，无法证明钱包所有权。
3. **周期性监控与状态**：后台将周期性检测钱包余额及 GRAM/USD 市场行情。即使当前无待付款订单，后台也会持续执行检测；新订单必须等待行情有效就绪后方可选择 GRAM 付款。
4. **付款人支付流程**：付款人选择 TON / GRAM，打开 Telegram「钱包」，点击右上角「扫一扫」扫描收银台展示的二维码，或点击「打开钱包付款」直接唤起钱包，复制页面显示的完整精确金额进行转账。仅支持转入原生 GRAM（网络手续费需付款人另付），切勿发送任何 Jetton 代币。

### 二维码与跳转协议

- **本地生成**：二维码由服务端本地生成，内容为订单锁定的收款地址，与 Telegram 钱包的标准地址二维码格式完全一致，不依赖任何第三方二维码服务。
- **钱包唤起协议**：收银台「打开钱包付款」链接使用 `ton://transfer/<address>?amount=<nanogram>` 协议，携带订单锁定的收款地址及以 nanogram 为单位的整数金额。
- **动态生命周期**：付款方式或金额发生变动时页面自动刷新；订单支付成功、主动取消或超时关闭后，二维码与钱包付款入口将自动隐藏。

### 持久化与检测周期

- **配置持久化**：后台配置通过 `settings.Patch` 写入 SQLite，服务重启后自动恢复。启动配置文件（YAML）仅保存基础监听、数据库路径与管理员登录项。
- **后台检测进程**：行情与余额定期检测由主服务进程在后台执行，服务退出后自动停止。
- **检测周期控制**：
  - 行情检测周期（`PriceInterval`）、余额检测周期（`BalanceInterval`）与行情时效上限（`MaxPriceAge`）详见 `internal/gram/monitor.go`。
  - 到账查询间隔由后台「到账查询间隔」配置控制（默认值见 `config.Default` 的 TON 配置）。
  - 若遇网络抖动、接口耗时较长、分页拉取或触发限流，两次成功检测之间的时间可能相应延长。

## Toncenter API 接口与收款证据

系统仅使用以下只读接口，**无需配置钱包私钥或助记词**：

- `getTransactions`：查询地址历史交易，强制使用 `archival=true`、`lt` 与 `hash` 进行分页。单纯拉取最近 10 条交易无法保证补齐业务高峰期或服务停机期间的全部流水。
- `getAddressBalance`：读取钱包余额；历史交易列表不能替代实时余额查询。

### 交易关键字段解析

| 交易字段 | 含义与系统处理规则 |
| --- | --- |
| `transaction_id.hash` | 交易唯一身份标识。与交易 BOC 的根哈希比对校验，转换为十六进制文本后用于流水去重及后台核对。 |
| `transaction_id.lt` | 逻辑时间（Logical Time），用于历史深度分页游标，非 Unix 时间戳。 |
| `utime` | Unix 时间戳（秒）。与 BOC 内记录的时间比对，用于付款有效时间窗口匹配。 |
| `in_msg.value` | 入站消息携带的原生代币数量，单位为 nanogram（除以 10^9 转换为 GRAM）。系统不会仅凭此字段直接确认到账。 |
| `data` | Base64 编码的交易 BOC。实际收款金额、收款账户、合约执行状态、退回标记与附言内容均从此字段完整解析。 |
| `out_msgs` | 出站消息列表。伴随转出或附带合约执行的复杂交易，不作为普通到账流水自动核销。 |

### 交易合法性判定规则

- **标准内部转账**：入站消息必须严格匹配收款地址，且无退回（bounce）、转出、状态初始化或复杂合约调用载荷。标准 TVM 执行路径要求交易状态为成功且未 aborted。
- **未初始化账户（NO_STATE）兼容**：允许未初始化账户接收 non-bounceable 类型的 `NO_STATE` 转账。此路径必须具备完整的信用阶段（credit phase）、信用金额与消息金额一致、无欠费扣收、账户状态为 `uninit`、无 action/bounce，且明确的信用额扣除存储费后仍为正数。在此路径下，`aborted` 仅代表未执行 action，不能视作资金退回。
- **拒绝自动核销情形**：其他 `skipped` 原因、标记为 `bounceable` 或处于冻结状态的账户，系统一律拒绝自动核销。纯文本备注或空消息转账可正常接收。
- **分页异常与容灾保护**：若遭遇 BOC 损坏、哈希/逻辑时间/时间戳/收款账户不一致、分页顺序异常或响应不完整，当前页处理判定失败，但系统保留已提交的 LT/Hash 检查点，并在下一轮扫描时从此检查点断点续传。
- **时间游标推进**：每轮扫描最多读取一页，仅当固定时间范围内的交易全部核对完成后方推进时间游标，不受单次 100 页上限影响。接口查询失败不会将订单误判为未付款关闭。后续的补查任务、独占档位、唯一认领与回调通知完全遵循 `store.Process` 的原子事务规则。
- **精度溢出防护**：TON 链上金额支持 9 位小数，而系统支付域采用 6 位小数。若到账流水末 3 位非零，系统保留原始金额证据并拒绝自动核销，绝不截断或四舍五入。流水严格由后台扫描核验，收银台不接受前端用户手工提交交易哈希。

## 实时报价与误差边界

### 行情源与容差策略

- **行情源**：采用 Kraken 交易所原生代币的 `TONUSD` 买一/卖一价格计算中间价，直接使用 USD 现货交易对。（Tonviewer 属于浏览器展示层；TonAPI 的 rates 接口在文档中明确限定为展示用途，因此不作为结算换算依据）。
- **价差与熔断保护**：当买卖价差超过中间价的 0.5%、响应不完整、价格非正、接口报错或报价超过时效上限时，系统自动暂停生成新报价。报价失败后系统保留上一版价格与检测时间供运维诊断，但该价格严禁用于新订单。

### 金额换算与订单锁定

- **十进制精确计算**：用户选择付款方式时，系统使用高精度十进制有理数计算 `USD 订单金额 / 每枚 GRAM 的 USD 价格`，向上对齐至 6 位小数，随后分配独占金额档位。
- **尾差上限控制**：舍入误差与订单识别尾差合计最大允许 0.1%；若无可用档位满足此上限，系统直接拒绝选择该付款方式，绝不放大尾差。此处的 0.1% 是基于本单所用基准报价的计算边界，不保证与其他交易所或后续时刻的市场波动一致。
- **金额固化**：订单生成后即刻锁定所用汇率、检测时间与完整应付代币数量。后续行情波动不影响已选定订单的应付金额；针对同一付款方式的重复刷新请求亦复用已锁定的金额。
- **商户回调口径**：发送给商户的回调参数中，`amount` 代表原始 USD 订单金额，`actual_amount` 代表实收 GRAM 数量。商户端须依据接入契约正确解析两者的单位差异。

### 监控接口

管理员鉴权接口 `GET <后台入口>/gram/status` 返回钱包余额、USD 价格、实时买卖价、检测时间戳、有效性状态与错误详情。该接口仅供运维监控与健康探测，不可作为付款凭据。

## 验证与验收

1. **自动化测试**：
   ```sh
   go test ./...
   go test -race ./...
   go vet ./...
   go build ./...
   ```
   测试用例覆盖真实链上样本的 BOC 解析、深度分页、重复交易去重、不安全到账拦截、精度溢出保护、报价过期熔断、尾差边界及回调验签。

2. **真实环境人工验收流程**：
   - 创建小额 USD 测试订单，在收银台选择 GRAM 支付；
   - 按照页面提示的完整精确金额发起链上转账，记录链上交易哈希；
   - 观察后台自动扫描核销并核对商户发货通知；重复请求不应触发二次认领；
   - 模拟中断行情源，确认新订单暂停生成报价，而已锁定金额的待付款订单仍可正常依据链上证据核销。自动化模拟测试与只读接口无法替代真实资金链路验收。

## 主链最终性门槛

仅通过 BOC 本地解析验证仍不足以触发订单核销。

为了防止分叉和分片重组风险，每页拉取的候选原生代币到账记录，还必须在 **Toncenter v3 交易索引** 中按账户、LT 和交易哈希进行精确匹配，并确认获得正数 `mc_block_seqno`（主链区块高度）、合法的分片引用，以及当前 masterchainInfo 主链高度不低于该序号。

- **最终性缺失保护**：若索引查询失败、HTTP 异常、索引尚未追平或身份不一致，当前页流水不提交入库，不推进检查点游标，留待下一轮继续重试。Store 层严禁写入无主链区块高度的 confirmed 证据。
- **限流预算共享**：每页处理最多增加两次共享限速预算的主链索引查询，不为单笔交易频繁发起独立请求。
- **信任边界说明**：此处的最终性校验基于对 Toncenter 主链索引的归属确认，不代表本地运行独立全节点或独立校验了完整的主链 Merkle/签名密码学证明。
